# Команда с выводом через Veyon

Отдельные действия «Команда с выводом» и «Команда с выводом всем» доступны администраторам и суперадминистраторам. Обычное действие «Выполнить команду» сохраняет прежнее поведение.

## Настройка

В настройках каждого MikroTik задайте «Обратное подключение CMNC (Loopback)»: полный HTTP/HTTPS URL сайта, доступный с ПК этого маршрутизатора, например `https://cmnc.example.local`. При нестандартном порте укажите его в URL. Это адрес CMNC, а не REST-адрес MikroTik и не `127.0.0.1` ученического ПК. Проверка TLS использует штатное доверие Windows; сертификат должен быть доверенным на клиентах.

В `.env`:

```env
CMNC_VEYON_COMMAND_RESULT_TIMEOUT_SECONDS=60
```

Сбор начинается при создании задания; по истечении срока неответившие ПК отмечаются тайм-аутом. Допустимый интервал — 5–3600 секунд. Обёртка оставляет небольшой резерв для возврата результата и ограничивает время дочернего PowerShell.

Обновление:

```bash
bash scripts/compose-up.sh cmnc-inventory-service cmnc-veyon-service cmnc-api-gateway cmnc-web
```

Inventory автоматически применяет миграцию `20261113_0006`; у существующих MikroTik адрес обратного подключения первоначально пустой. Без настройки команда с выводом не отправляется. Proxy Veyon менять не требуется.

## Работа

Veyon запускает короткую PowerShell-обёртку. Она получает скрипт задания с CMNC, запускает команду в дочернем Windows PowerShell и возвращает stdout, stderr, код завершения и признаки обрезки/тайм-аута. Выполнение идёт с правами сеанса, в котором Veyon запускает приложения; повышения до SYSTEM или администратора эта функция не добавляет.

Для массовых заданий используются закреплённые устройства аудитории; устройства с защитой от массового управления Veyon исключаются. Защита WAN и WoL не исключает их из команд Veyon. Индивидуальные действия сохраняют доступ к устройствам с массовой защитой.

В окне результатов ответы появляются по мере завершения отдельных ПК. Это окончательные результаты каждого процесса, а не потоковая терминальная сессия. Неполученные ответы отмечаются тайм-аутом. Закрытие окна не отменяет уже запущенные команды.

Каждый поток ограничен 65 536 символами; оставшийся поток считывается и отбрасывается, чтобы процесс не блокировался на заполненном канале. Временный скрипт на ПК удаляется после завершения. Команда запускается без постоянного изменения ExecutionPolicy; параметр Bypass применяется только к дочернему процессу.

## Хранение и доступ

Задания и результаты сохраняются в `command-jobs.sqlite3` в существующем томе Veyon (`/data`). Команды зашифрованы ключом этого тома. Токены результатов хранятся только в виде SHA-256 и привязаны к заданию/ПК, имеют срок действия и принимают один итоговый ответ. Они передаются в HTTP Authorization, а не в URL. Результаты читает только создатель задания с текущим доступом к аудитории.

После перезапуска сервиса задания автоматически повторно не отправляются. Старые данные удаляются при следующем чтении/создании задания после десяти минут с момента окончания срока сбора. Тексты команд и результатов не записываются в access-логи.
