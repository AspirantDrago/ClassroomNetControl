# Пользователи устройств и история сеансов

Фоновый сбор выполняет `cmnc-veyon-service`, независимо от открытых страниц. Он получает закреплённые устройства активных аудиторий и их доступность из `cmnc-classroom-service`, затем читает `/api/v1/user` через существующую интеграцию Veyon. Приоритет имеет ключ аудитории; ключ MikroTik используется только при отсутствии собственного. Не требуется новый доступ к MikroTik или агент Windows.

API Veyon: https://docs.veyon.io/en/latest/developer/webapi.html#user-information

Настройки `.env`:

```dotenv
CMNC_VEYON_USER_POLL_INTERVAL_SECONDS=30
CMNC_VEYON_USER_POLL_CONCURRENCY=2
```

Интервал опроса каждого устройства — 5–3600 секунд; одновременно опрашиваются 1–8 устройств. У каждого устройства отдельное расписание, здоровые цели отсчитывают интервал от начала предыдущего запроса. Ожидание завершения общего обхода отсутствует. Для больших инсталляций можно увеличить параллельность. Новые подключения, созданные только для опроса пользователя, закрываются после чтения; подключения просмотра экрана сохраняются.

Известный логин показывается на вкладке «Инфо». Пустой логин при готовом сеансе отображается как `—`. При выключенном ПК, ошибке связи/ключа, неготовом сеансе или устаревшем наблюдении поле пустое. Данные приходят вместе с API аудитории, отдельные запросы браузера не нужны.

Миграция classroom-service `20261115_0011` создаёт таблицы текущих наблюдений и интервалов. Одинаковые последовательные наблюдения продлевают интервал, смена логина создаёт новый. Срок свежести — максимум из 90 секунд и трёх настроенных интервалов опроса. После истечения срока история остаётся с пропуском; старые сведения не продолжаются бессрочно. Наблюдения для другого IP, MikroTik, аудитории, незакреплённого устройства и неактивной аудитории отбрасываются. Изменения сериализуются блокировкой устройства.

В статистике первая дорожка — пользователи: серый — пользователь отсутствует, бежевый — авторизован, пропуск — нет данных. Подсказка авторизованного интервала содержит логин. Легенда отражает все три состояния. История до установки обновления не восстанавливается.

Обновить только затронутые сервисы:

```bash
bash scripts/compose-up.sh cmnc-classroom-service cmnc-veyon-service cmnc-api-gateway cmnc-web
```

Миграция выполняется при старте classroom-service. Docker Compose использует указанные значения по умолчанию, даже если новые строки ещё не добавлены в серверный `.env`.

Домен в логине скрывается только при отображении (как `DOMAIN\user`, так и `user@domain`); БД и API сохраняют исходную строку. Между интервалами есть видимая граница. При смене двух авторизованных учётных записей без потери свежести время перехода принимается равным последнему успешному наблюдению старого пользователя. Это оценка по опросам, а не точное событие входа. Через устаревшие данные переход не переносится: пропуск сохраняется.

В карточках логин показывается над загруженной миниатюрой, а в описании — последней строкой перед кнопкой Интернета. При отсутствии логина над миниатюрой строка не резервируется, в описании отображается `—`. Длинные подписи обрезаются с троеточием.

## Независимое расписание

Список целей обновляется отдельно от опросов. Ограниченное число исполнителей выбирает готовые цели; ответы сразу сохраняются отдельными запросами. Для одного device_id одновременно выполняется не более одного опроса, в том числе при удалении и повторном появлении цели. Поздний результат после изменения IP/аудитории/доступности отбрасывается.

Ранее обход мог занимать больше срока свежести 90 секунд: на рабочем сервере наблюдались интервалы около 91,8 секунды, что давало регулярные пропуски. Теперь работающие цели имеют приоритет среди готовых, а ошибки и отсутствие Veyon увеличивают паузу повторов (до максимума из 300 секунд и базового интервала). Смена ключа сбрасывает эту задержку. Лимит параллельности сохраняется, поэтому при полной загрузке исполнителей запрос может начаться позже срока; данные не продолжаются бессрочно. Реальные потери связи и истечение свежести по-прежнему образуют пропуски.

Для установки только изменения планировщика достаточно:

```bash
bash scripts/compose-up.sh cmnc-veyon-service
```

Новые параметры `.env` и миграции не требуются. Ранее сохранённые пропуски не переписываются.

## Устройства без Veyon

Флаг «Не ПК (нет Veyon)» (`is_non_pc`, по умолчанию false) хранится миграцией `20261115_0012`. При включении API принудительно включает защиту от массового Veyon, завершает текущее наблюдение пользователя и исключает устройство из списка фонового опроса. Поздние ответы для него не сохраняются. Прямые Veyon-запросы gateway отклоняет с 409.

В UI нет имени пользователя на карточке, миниатюр, вкладок экрана/перехвата, кнопок Veyon и полосы пользователей в статистике. Рамка карточки синяя. Массовые Veyon и WAN-операции исключают такие устройства, не учитывая их как пропущенные или не выполненные. Индивидуальное управление WAN остаётся по обычным правам. WoL сохраняется, пока не запрещён защитой WoL. При снятии флага защита от массового Veyon остаётся включённой и снова доступна для изменения.

Установка флага требует обновить classroom-service, gateway и WEB; перезапуск veyon-service для исключения целей не требуется — планировщик обновляет список автоматически.
