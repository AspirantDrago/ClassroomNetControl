# Интеграция Veyon

## Состав

- `cmnc-veyon-proxy` — отдельный Veyon WebAPI Proxy 4.11.4 на Ubuntu 24.04.
  Используется официальный deb-пакет Veyon с закреплённой SHA-256, а не устаревший
  опубликованный образ. Он принимает WebAPI-запросы и подключается к Veyon Server на ПК.
- `cmnc-veyon-service` — хранение ключей, выбор ключа, соединения с устройствами,
  получение экрана и команды питания.
- API gateway проверяет доступ пользователя к аудитории при каждом запросе.
  Браузер не получает приватные ключи и внутренние идентификаторы подключений Veyon.

HTTP API proxy и интеграционного сервиса доступны только во внутренней сети Compose.
Для демонстрации экрана браузера или ПК публикуется отдельный TCP-порт ретранслятора
(по умолчанию 11400); получатели подключаются к нему по токену своей демонстрации. API/Web не ждут Veyon при запуске; недоступность
Veyon влияет только на экран и управление питанием. Интеграционный сервис ждёт
готовности своего proxy-контейнера. База PostgreSQL и RabbitMQ ему не нужны.

Официальные материалы: [WebAPI](https://docs.veyon.io/en/latest/developer/webapi.html),
[WebAPI Proxy](https://github.com/veyon/webapi-proxy),
[релиз Veyon 4.11.4](https://github.com/veyon/veyon/releases/tag/v4.11.4).

## Настройка ключа

1. В Veyon Configurator экспортируйте **приватный** ключ нужной пары, например `CMNC`,
   в PEM-файл. На рабочих ПК должен быть соответствующий публичный ключ той же пары.
2. В приложении откройте редактирование MikroTik или аудитории. После создания
   нового объекта его нужно сохранить и снова открыть редактирование.
3. В блоке «Veyon — ключ аутентификации» укажите точное имя ключа (`CMNC`), выберите
   приватный PEM-файл либо вставьте его содержимое и нажмите «Сохранить ключ Veyon».
   Этот блок сохраняется отдельно от основной формы объекта.
4. Ключ аудитории имеет приоритет над ключом MikroTik. При ошибке этого ключа
   сервис не переключается на ключ MikroTik автоматически. Удаление ключа аудитории
   разрешает использование общего ключа MikroTik.

Поддерживаются незашифрованные приватные RSA-ключи PEM до 64 КБ. Сам ключ после
сохранения больше не возвращается в браузер: отображаются только имя и факт настройки.
Настраивать ключи могут пользователи с правом управления аудиториями/MikroTik.

На устройствах нужны работающая Veyon Service, аутентификация по ключам и разрешение
соответствующего доступа в Veyon. TCP-порт устройств по умолчанию — 11100;
его можно изменить переменной `CMNC_VEYON_TARGET_PORT` на сервере. WebAPI на каждом
рабочем ПК включать не требуется: его роль выполняет отдельный proxy-контейнер.
IP устройства должен находиться в подсети аудитории и быть доступен с сервера.

## Экран и питание

- В окне закреплённого устройства есть вкладка «Экран». Пока она открыта,
  частота обновления автоматически подстраивается под время загрузки и декодирования
  кадра, до 10 кадров/с. Параллельные запросы от одного просмотра не накапливаются. После ошибки
  повтор выполняется через 3 секунды. Кадры не сохраняются на диске и не кешируются.
- При закрытии вкладки/окна обновление прекращается; при скрытой вкладке браузера
  новые кадры не запрашиваются. Неактивные соединения Veyon закрываются автоматически.
- На вкладке «Инфо» доступны «Выключить» и «Перезагрузить» с подтверждением.
- На странице аудитории доступна «Выключить все» с обязательным подтверждением.
  Команда относится к закреплённым устройствам без защиты от массового управления,
  включая защищённые от отключения WAN.
  Защита WAN не является защитой от выключения питания.
- Просмотр и питание доступны всем, кто имеет доступ к данной аудитории/устройству.
  Команды не блокируются только из-за состояния online/offline из DHCP.
- Групповое выключение отправляет максимум четыре запроса одновременно и показывает
  число принятых команд и ошибок. Повторы команд питания автоматически не выполняются.
  Ответ «команда отправлена» означает принятие команды Veyon, а не подтверждение выключения ПК.

## Хранение и резервное копирование

Ключи хранятся зашифрованными в томе `cmnc_veyon_data` (SQLite + Fernet).
Ключ шифрования находится в том же защищённом томе; файлы доступны владельцу контейнера.
Резервная копия должна включать **весь том**, в том числе `master.key` и `keys.sqlite3`.
Стандартная резервная копия PostgreSQL эти данные не включает.
После потери `master.key` существующие зашифрованные ключи восстановить невозможно.
Не удаляйте том при обновлении контейнеров.

## Применение на сервере

Из корня проекта:

```bash
bash scripts/compose-up.sh cmnc-veyon-proxy cmnc-veyon-service cmnc-api-gateway cmnc-web
```

Скрипт с явно указанными сервисами использует `--no-deps`, поэтому proxy тоже указан
явно. При первом запуске будет создан том ключей. Миграции существующих баз не требуются.
Пакет proxy закреплён для архитектуры AMD64; для ARM64 нужен соответствующий официальный пакет.

Проверка:

```bash
docker compose -f infra/docker-compose.yml --env-file .env ps cmnc-veyon-proxy cmnc-veyon-service
docker logs --tail 100 cmnc-veyon-service
```

Проверка на тестовом стенде не выполняет команд питания на реальных ПК.
После установки загрузите ключ, откройте экран одного ПК и проверьте отдельную команду.

При подготовке первого кадра сервис ожидает изображение на уже открытом подключении.
Временный ответ FramebufferNotAvailable не закрывает сеанс и не запускает аутентификацию заново.


## Если изображение не появляется

После открытия вкладки «Экран» проверьте журнал интеграции:

```bash
docker logs --since 5m cmnc-veyon-service
```

Запись `Veyon authenticated` означает успешную аутентификацию. Если изображение
не поступает, запись `Veyon framebuffer unavailable` содержит возраст соединения,
идентификатор и длительность сеанса, признак входа пользователя либо статус ошибки
запроса этих сведений. Она выводится не чаще раза в минуту для соединения.
Приватный ключ, идентификатор подключения и имена пользователей не записываются.
Для диагностики также нужны версия Veyon на ПК и результат команды питания.
Не включайте отладочное логирование WebAPI: оно может раскрыть тело запроса с ключом.


## Режимы просмотра и несколько зрителей

Кнопка «На весь экран» использует полноэкранный режим браузера (выход — Esc).
Кнопка «В отдельном окне» открывает независимый просмотр;
окно может открыться вкладкой в зависимости от браузера. Разрешите всплывающие окна
для этого сайта. Встроенный просмотр на это время приостанавливается. При закрытии
отдельного окна просмотр возвращается в окно устройства, если оно ещё открыто.
Отдельное окно продолжает работать после закрытия окна устройства или перехода
в другую аудиторию. Оно использует обычную авторизацию приложения и проверку прав.
Скрытый просмотр приостанавливает получение кадров.

Соединение с ПК переиспользуется для одного адреса и пары ключ/имя ключа. Последний
успешный JPEG хранится только в памяти сервиса, до следующего кадра либо закрытия
соединения. Запросы на ту же ширину могут использовать его в течение 100 мс:
параллельные зрители не создают дополнительные подключения к ПК и не запрашивают
одинаковый кадр у proxy одновременно. Проверка прав выполняется на каждом запросе.
Кадры не хэшируются и не сохраняются на диск; браузеру отправляется `no-store`.
Сетевой трафик от сервера к браузерам растёт с числом зрителей.

Proxy настроен на интервал мониторинга 100 мс. Частота в браузере учитывает загрузку
и декодирование со сглаживанием; при задержках она снижается автоматически.
Это получение отдельных JPEG через WebAPI, не видеопоток с гарантированной частотой.


## Защита устройства от массового управления

На вкладке «Настройка» устройства есть флажок «Защита от массового управления через Veyon».
По умолчанию он выключен, в том числе у существующих устройств после миграции.
При включении устройство исключается из массовых команд Veyon над аудиторией.
Исключение применяется на сервере; защищённые устройства не считаются ошибками,
а возвращаются в `skipped_count`. Подтверждение учитывает только устройства без защиты.
Если защищены все устройства, кнопка «Выключить все» недоступна.

Просмотр экрана, выключение и перезагрузка из окна конкретного устройства остаются
доступны пользователям с доступом к аудитории. Защита не влияет на WAN и WoL,
которые выполняются через MikroTik.

При обновлении требуется перезапуск сервиса аудиторий (он автоматически применяет
миграцию), затем API и веб-интерфейса. Контейнеры Veyon менять не требуется.


## Защита от массового пробуждения WoL

Флажок «Защита от пробуждения WoL» на вкладке «Настройка» по умолчанию выключен,
в том числе у существующих устройств после миграции. Защищённые устройства
исключаются на сервере из команды «Разбудить всё»; ответ содержит `skipped_count`.
Если защищены все устройства, кнопка массового пробуждения недоступна.
Кнопка «Разбудить» в окне устройства продолжает работать. Защиты WoL, WAN и Veyon
независимы друг от друга.


## Удалённое управление

Вкладка «Перехват экрана» доступна тем же пользователям, которым доступно устройство.
Нажмите на изображение, чтобы захватить ввод. Поддерживаются перемещение мыши,
левая/правая/средняя кнопки, перетаскивание, прокрутка, служебные клавиши и Unicode
(включая кириллицу). На сенсорном экране касание и перемещение передают указатель.
Esc освобождает ввод. Нажатие вне изображения, скрытие страницы, переключение вкладки
и закрытие окна завершают захват. Полноэкранный режим и отдельное окно доступны
так же, как для просмотра. Вкладка «Экран» не передаёт ввод.

Один ПК может иметь только одно активное окно управления; параллельный просмотр
разрешён. Сеанс управления принадлежит пользователю и защищён случайным токеном.
Каждый запрос проходит проверку доступа к аудитории. При отсутствии heartbeat
8 секунд сервер освобождает управление и отпускает нажатые клавиши/кнопки.
События ввода не повторяются автоматически и не пишутся в журналы приложения.
Браузерные и системные сочетания, которые браузер не отдаёт странице, не передаются.
Защита от массового управления не ограничивает эту индивидуальную операцию.

В штатном WebAPI 4.11.4 нет передачи пользовательского ввода. При сборке proxy
CMNC добавляет маршрут `POST /api/v1/input` в плагин WebAPI из закреплённых исходников
Veyon 4.11.4. Он использует существующее аутентифицированное подключение, проверяет
пакет целиком и передаёт события в `VncConnection`. Публичный доступ к этому маршруту
не предоставляется. Изображение по-прежнему получается через WebAPI.
Исходная версия и контрольная сумма закреплены в `Proxy.Dockerfile`, изменения
находятся в `services/cmnc-veyon-service/native-input` (GPL-2.0-or-later, как Veyon).

Обновить proxy, сервис, API и интерфейс:

```bash
bash scripts/compose-up.sh cmnc-veyon-proxy cmnc-veyon-service cmnc-api-gateway cmnc-web
```

Первая сборка proxy с расширением требует загрузки зависимостей компиляции.
Компилятор и исходники остаются в промежуточном образе, рабочий контейнер получает
только собранный плагин. Новых миграций базы не требуется.


## Дополнительные массовые команды питания

В ряду «Питание» есть «Перезагрузить всё» (серая кнопка) и «Установить обновления
и выключить все» (красная). Обе требуют подтверждения и пропускают устройства
с защитой от массового управления через Veyon. При отсутствии подходящих
закреплённых устройств кнопки скрыты, включая случай защиты всех устройств.
Положение устройства в сетке не влияет на участие в команде.

Перезагрузка доступна пользователям с доступом к аудитории. Установка обновлений
с выключением доступна только ролям `admin` и `superadmin`: проверка применяется
в API, а не только в интерфейсе. Veyon использует штатную команду
`InstallUpdatesAndPowerDown` (UUID `09bcb3a1-fc11-4d03-8cf1-efd26be8655b`).
Ответ подтверждает отправку команды, а не завершение обновления или выключения.

Для обновления нужны `cmnc-veyon-service`, `cmnc-api-gateway`, `cmnc-web`.
Proxy и схема базы не меняются.


## Миниатюры в аудитории

Переключатель «Описание ↔ Миниатюры» находится под кнопками управления аудиторией.
При каждом открытии страницы миниатюры включены; выбор режима действует до перезагрузки страницы. В режиме «Описание» запросы
миниатюр прекращаются. Миниатюры работают в сетке и у закреплённых устройств
без позиции. У выключенных устройств, при отсутствии/ошибке получения кадра
отображаются прежние сведения. Кнопка WAN остаётся видимой. Наведение мыши на
карточку временно показывает описание; на телефоне используйте переключатель.

```dotenv
CMNC_WEB_THUMBNAIL_REFRESH_INTERVAL_MS=1000
CMNC_WEB_THUMBNAIL_CONCURRENCY=4
```

Интервал задаётся в миллисекундах, минимум 100 мс. Пустое или некорректное значение
заменяется на 1000 мс. Это настройка сборки: после изменения `.env` пересоберите
`cmnc-web` через `scripts/compose-up.sh`. Период отсчитывается от начала предыдущего
запроса, параллельные запросы одной карточки не накапливаются.

Запрашиваются кадры шириной 320 пикселей. Число одновременных запросов задаётся
`CMNC_WEB_THUMBNAIL_CONCURRENCY` (положительное целое число, по умолчанию 4); карточки вне видимой области, скрытая страница и выключенные устройства
не опрашиваются. Полученные изображения не сохраняются на диск, временные URL
освобождаются при замене кадров, отключении режима и смене аудитории.
Проверка доступа к устройству выполняется для каждого кадра так же, как в «Экран».

Миниатюра занимает всю внутреннюю ширину карточки без боковых отступов,
сохраняет пропорции и отступ сверху. Карточки каждого ряда выравниваются по высоте
самой высокой карточки, кнопки WAN располагаются снизу.


## Аварийные перезапуски proxy

Статус Docker `healthy` означает, что порт отвечает сейчас, и не исключает
недавних аварийных перезапусков. Строка `Aborting due to severe error` выводится
обработчиком аварийных сигналов Veyon на Linux; сама по себе она не называет
конкретное место сбоя.

Proxy запускается с `VEYON_LOG_LEVEL=warning`. Это сохраняет ошибки, аварийный сигнал
и `BACKTRACE` в Docker-журнале, обходя отключение обычных сообщений в `veyon-cli`.
Уровень debug не включается: WebAPI на этом уровне может выводить приватные ключи
из запросов аутентификации и события пользовательского ввода.

Файловый журнал перенесён в `/tmp/veyon-logs`, принадлежащий UID 10001. Файлы
ограничены 10 МБ с двумя ротациями. Это исключает конфликт с `/tmp/VeyonCLI.log`,
созданным от root во время сборки. Сообщение Veyon `is a symlink` может означать
неудачное безопасное открытие файла из-за прав; оно не доказывает наличие ссылки.

В Qt HTTP Server 6.4.2 воспроизведён сбой при отключении HTTP-клиента до
завершения аутентификации Veyon: отложенный ответ обращался к уже удалённому
сокету и связанному объекту запроса. Сбой возможен даже при одном
запросе к недоступному устройству; большой параллелизм увеличивает вероятность.
Ранее наш HTTP-клиент ждал 12 секунд при тайм-ауте Veyon 15 секунд.

Образ proxy собирает Qt HTTP Server 6.4.2 с проверкой времени жизни сокета через
`QPointer` перед отправкой отложенного ответа. Остальные библиотеки Qt остаются
штатными. Исходники закреплены SHA-256, патч останавливает сборку при несовпадении
ожидаемого кода. Время ожидания аутентификации в сервисе увеличено до 20 секунд.
Отмена запросов пользователем также безопасна; уменьшать параллелизм для этого
исправления не требуется. `CMNC_WEB_THUMBNAIL_CONCURRENCY=100` можно сохранить.

Для применения пересоберите только proxy и сервис Veyon:

```bash
bash scripts/compose-up.sh cmnc-veyon-proxy cmnc-veyon-service
docker logs --since 5m --timestamps cmnc-veyon-proxy 2>&1
```

Регрессионный тест запускает изолированный контейнер, отправляет запросы
аутентификации к закрытому локальному порту, обрывает HTTP-соединения и проверяет
работоспособность proxy после завершения попыток аутентификации. Реальные ПК
и ключи не используются. Для запуска с собранным образом:

```bash
CMNC_TEST_VEYON_PROXY_IMAGE=cmnc-veyon-proxy:socket-fix-validation \
CMNC_TEST_VEYON_DISCONNECT_CLIENTS=100 \
python -m pytest services/cmnc-veyon-service/tests/test_proxy_disconnect.py -q
```


## Снимок экрана

На вкладке «Экран» первая кнопка справа — «Снимок». Она доступна также
в отдельном окне просмотра. Снимок загружается пользователю как PNG с названием
аудитории в начале, названием ПК, локальной датой и временем в имени:
`TikTok_PC-01_2026-11-08_16-30-45.png`. Кнопка «Снимок» зелёная.

Используется штатный WebAPI Veyon `/api/v1/framebuffer` с `format=png`,
без `width`/`height`: исходное разрешение, сжатие без потерь. Снимок запрашивается
отдельно от уменьшенного JPEG трансляции и миниатюр, их кэш не используется.
Proxy получает исходные кадры в режиме Highest (без потерь), чтобы PNG не содержал
артефакты предварительного JPEG-сжатия. Это увеличивает трафик от ПК к proxy;
трансляция в браузер остаётся JPEG, миниатюры — уменьшенными. Проверка доступа к устройству обязательна для каждого запроса. Кадр не хранится
на серверном диске. Дата и время в имени отражают получение снимка браузером.

Для применения нужны только:

```bash
bash scripts/compose-up.sh cmnc-veyon-proxy cmnc-veyon-service cmnc-api-gateway cmnc-web
```


## Запись экрана

На вкладке «Экран» и в отдельном окне просмотра кнопка «Запись» открывает
настройки качества и FPS. Три уровня качества: ширина до 1920/1280/854 пикселей,
JPEG исходных кадров 95/85/70, битрейт видео 6/3/1,2 Мбит/с. Увеличения исходного
разрешения нет; пропорции сохраняются. Доступны 1, 5, 10, 15, 25 и 30 FPS.
Это целевая частота записи: количество новых кадров зависит от ПК, Veyon,
сети и производительности браузера. При записи опрос не ограничен обычными
10 FPS просмотра, запросы не накладываются друг на друга.

Основной формат — WebM / VP9. Браузер автоматически выбирает поддерживаемый
вариант через MediaRecorder.isTypeSupported: VP9 → MP4/H.264 → MP4 → WebM/VP8.
AV1 не требуется, чтобы не ограничивать совместимость и не перегружать
программное кодирование. Звук не записывается.

После запуска показаны таймер, «Отмена», «Пауза»/«Продолжить», «Завершить».
Отмена удаляет запись без скачивания. Завершение и достижение лимита сохраняют
файл с аудиторией, ПК, датой и временем начала. Паузы не входят в длительность.
Переход на другую вкладку устройства или закрытие его окна завершает и сохраняет
запись. Перенос в отдельное окно во время записи отключён; сначала откройте
нужное окно, затем запускайте запись. Страницу сайта во время записи следует
оставлять открытой: перезагрузка или закрытие всего браузера прервёт запись.
ОС и браузер могут замедлить захват в фоновом режиме.

Там, где доступен выбор файла для записи, браузер пишет фрагменты прямо в файл.
В остальных браузерах фрагменты временно сохраняются в IndexedDB и скачиваются
после завершения. Вся запись не накапливается в массиве в оперативной памяти.
Нужен достаточный объём свободного места и доступ к хранилищу браузера.
Обработчики ошибок останавливают запись, пытаясь сохранить доступную часть.
На сервере видеозаписи не создаются; каждый исходный кадр проходит обычную
проверку доступа к устройству.

```dotenv
CMNC_WEB_RECORDING_MAX_DURATION_SECONDS=5400
```

Лимит по умолчанию — 90 минут активной записи. Положительное целое число задаёт
лимит в секундах, неверное значение заменяется на 5400. Настройка применяется
при сборке `cmnc-web`. Для первого обновления с поддержкой качества кадров:

```bash
bash scripts/compose-up.sh cmnc-inventory-service cmnc-veyon-service cmnc-api-gateway cmnc-web
```

При последующем изменении только лимита достаточно пересобрать `cmnc-web`.

## Длительность WebM, перемотка и FPS

Перед сохранением WebM выполняется финализация: добавляются Duration, SeekHead
и Cues с позициями ключевых кадров. Видеоданные не перекодируются; большие
данные обрабатываются срезами Blob. Это применяется к скачиванию и прямой записи
в файл. Проверки браузера требуют конечной длительности и успешного перехода
в середину видео. Запись по согласованию остаётся без звука.

Заголовок окна показывает «Аудитория: устройство». Во вкладках «Экран» и
«Перехват экрана» рядом серым текстом отображается измеренный FPS получения
и декодирования кадров за последнюю секунду, включая период записи.
В отдельном окне название и FPS также видимы над изображением.

Целевая частота обычного просмотра повышена до 30 FPS; интервал proxy уменьшен
со 100 до 33 мс, общий кэш сервиса — со 100 до 25 мс. Опрос остаётся
последовательным с адаптацией к задержкам. Реальная частота зависит от нагрузки,
кодирования JPEG и сети; WebAPI получает кадры отдельными HTTP-запросами.
Veyon Master работает через собственное соединение, поэтому равная плавность
не гарантируется. Для применения изменений нужны:

```bash
bash scripts/compose-up.sh cmnc-veyon-proxy cmnc-veyon-service cmnc-web
```

## Сокращение накладных расходов получения кадров

API Gateway повторно использует HTTP-соединения к внутренним сервисам и Veyon
в течение жизни приложения и закрывает их при остановке. Проверки пользователя,
доступа к аудитории и IP устройства по-прежнему выполняются на каждом кадре;
права и маршруты устройств не кэшируются. Сроки ожидания файловых операций
сохранены. В браузере убрана дополнительная задержка 5% после медленного кадра,
при этом запросы кадров остаются последовательными и ограниченными целевым FPS.
Индикатор округляется до ближайшего целого и имеет цвет #35373b.

Сравнение трёх вариантов на локальном стенде (20 цепочек по 5 HTTP-запросов):
новые клиенты — 44,53 мс на цепочку; новые клиенты без чтения окружения —
33,09 мс; повторное использование клиента — 2,76 мс. Это только накладные
расходы HTTP, без реального ПК, Veyon, JPEG и сети сервера, а не замер FPS
приложения в рабочей аудитории. Воспроизведение: `python scripts/benchmark-http-pool.py`.

Для применения: `bash scripts/compose-up.sh cmnc-api-gateway cmnc-web`.


## Специальные клавиши при захвате

Физическая клавиша Esc освобождает мышь и клавиатуру и выходит из полноэкранного
режима. Для передачи Esc удалённому ПК служит кнопка «Esc» на вкладке
«Перехват экрана». Красная «Ctrl+Alt+Del» расположена непосредственно слева
от «На весь экран», видна только admin/superadmin; API также проверяет роль.
Комбинация передаётся так же, как в Veyon Master: Control_L, Alt_L, Delete, затем отпускание в обратном порядке.
Обе кнопки работают через принадлежащий пользователю эксклюзивный сеанс
захвата, соблюдают порядок предшествующего ввода и отпускают отправленные
клавиши в обратном порядке. Проверка доступа к устройству обязательна.

Для обновления: `bash scripts/compose-up.sh cmnc-api-gateway cmnc-web`.

## Качество просмотра и перехвата

Шестерёнка справа от «В отдельном окне» открывает выбор качества: экономное
854/JPEG60, среднее 1280/JPEG75 (по умолчанию), высокое 1920/JPEG95,
максимальное 1920/JPEG100. Выбор сохраняется в cookie cmnc_screen_quality
на год (Path=/, SameSite=Lax, Secure на HTTPS) и общий для просмотра, перехвата
и отдельных окон в этом браузере. Отмена не меняет cookie. При возврате фокуса
окно перечитывает настройку. Неизвестное значение заменяется средним.
Качество записи по-прежнему задаётся в её собственном диалоге, PNG-снимок
остаётся в исходном разрешении. Для применения: `bash scripts/compose-up.sh cmnc-web`.

По умолчанию для просмотра и перехвата используется экономное качество
(до 854 px, JPEG60). Добавлено низкое качество (до 600 px, JPEG45).
Сохранённый выбор cookie сохраняет приоритет; отсутствие или некорректная
cookie теперь приводит к экономному качеству.

## Вкладка «Действия» устройства

Вкладка находится справа от «Перехват экрана». Группы: Интернет, Питание,
Авторизация, Внимание, Команды. WAN, WoL, выключение и перезагрузка используют
те же обработчики, что «Инфо». Защита WAN и права доступа сохраняются.
Прямые действия не исключаются защитой от массового управления.

Дополнительные действия используют штатные функции Veyon. Выключение после
подтверждения показывает запрос на удалённом ПК; таймер задаётся в часах,
минутах и секундах (от 1 секунды до 7 дней) и исполняется самим Veyon на ПК,
а не браузерным таймером. Вход запрашивает логин и пароль, выход требует
подтверждения. «Погасить экран» включает ScreenLock, «Разрешить экран» выключает
его. Сообщения и команды допускают многострочный текст, сайты — только HTTP(S).

Выполнение команды и установка обновлений с выключением доступны только
admin/superadmin, ограничения проверяются API. Команда запускается через
PowerShell в сеансе пользователя Windows: многострочный текст передаётся через
EncodedCommand (UTF-16LE), а не исполняется на сервере CMNC.
Пароль входа не сохраняется в cookie или хранилище браузера и маскируется
в представлении и JSON модели. Передаётся только для команды входа.
Ответ подтверждает отправку команды, а не факт выполнения на устройстве.

Для применения:

```bash
bash scripts/compose-up.sh cmnc-inventory-service cmnc-veyon-service cmnc-api-gateway cmnc-web
```


## Демонстрация экрана

В группе «Демонстрация» на странице аудитории и во вкладке «Действия» устройства
доступны четыре операции: собственный экран или экран выбранного ПК,
в полноэкранном или оконном режиме. Режим относится к окну Veyon на получателях.
При выборе ПК в диалоге укажите источник из той же аудитории. Источник не получает
собственную демонстрацию. Для демонстрации на единственный ПК выберите другой ПК
как источник либо собственный экран браузера.

«Собственный экран» открывает стандартный диалог браузера, где можно выбрать экран,
окно или вкладку. Для него требуется **HTTPS** (либо localhost); обычный HTTP
на `cmnc.ittop.loc` не разрешает `getDisplayMedia`. Звук не передаётся.
Браузер отправляет JPEG 1280×720 с сохранением пропорций, без очереди старых кадров,
не чаще 10 кадров/с. Сервер хранит только последний сжатый кадр в памяти и отдаёт его
всем получателям через RFB/Tight JPEG с токен-аутентификацией Veyon.

В форме создания/редактирования **каждого MikroTik** задайте:

- «Сервер демонстрации CMNC» — IP или DNS, доступный с его ПК, без протокола/пути/порта;
- «Порт демонстрации CMNC» — TCP-порт, видимый получателям (по умолчанию 11400).

Например: для Академии `192.168.10.11:11400`, а для филиала — его доступный адрес
CMNC и порт перенаправления. При NAT внешний порт может отличаться от порта
прослушивания сервера. Перенаправление должно вести к тому же ретранслятору CMNC;
указание порта в форме само по себе не меняет Docker и правила маршрутизатора.
Пустой адрес отключает запуск демонстраций для этого MikroTik. У существующих
записей после миграции адрес пустой, порт 11400; данные маршрутизаторов сохраняются.

Адрес выбирается по MikroTik **аудитории-получателя**, в том числе при источнике
из другой аудитории. Значения проверяются сервером и фиксируются в сеансе;
редактирование настроек применяется к следующим запускам без разрыва текущего.
Глобальные `CMNC_VEYON_DEMO_HOST` и `CMNC_VEYON_DEMO_PORT` больше не используются.
WireGuard с маршрутизацией и NAT поддерживаются: аутентификация получателя
не привязана к его видимому IP.

В `.env` остаются технические настройки серверного процесса и захвата:

```dotenv
CMNC_VEYON_DEMO_LISTEN_PORT=11400
CMNC_VEYON_DEMO_FPS=10
CMNC_VEYON_DEMO_QUALITY=100
```

`CMNC_VEYON_DEMO_LISTEN_PORT` — порт, который процесс слушает и Docker публикует
на Ubuntu Server. Это не внешний порт, задаваемый в настройках MikroTik.
По умолчанию оба равны 11400. Получателям требуется TCP-доступ к адресу/порту
из настроек их MikroTik.

Для выбранного ПК при запуске автоматически выбирается маршрут **для каждого
получателя**. Кандидаты прямого режима должны принадлежать тому же MikroTik и
подсети, что и источник. Совпадение подсетей само по себе не доказывает доступность.

Если для MikroTik настроено «Обратное подключение CMNC (Loopback)», сервер запускает
на источнике штатный DemoServer Veyon и отправляет получателям фиксированную
служебную проверку PowerShell со скрытым окном. Проверка подключается только к IP
выбранного источника на TCP 11400, проходит токен-аутентификацию Veyon и проверяет
инициализацию экрана. Она не принимает пользовательский текст команды и возвращает
только признак доступности через одноразовый токен. Обычные произвольные команды
по-прежнему доступны только администраторам; публичного API запуска произвольного
скрипта от имени преподавателя не добавляется.

Прошедшие проверку получатели подключаются **напрямую к ПК-источнику**. Для остальных,
включая отсутствие ответа, блокировку PowerShell/брандмауэра или ненастроенный Loopback,
используется **ПК → Veyon proxy / CMNC → получатели**. При смешанном режиме работают
нативный DemoServer и одна серверная задача захвата для получателей через CMNC.
Если прямых получателей нет, DemoServer источника останавливается. В интерфейсе
отображается число прямых и серверных подключений. Выбор делается при каждом запуске;
непрерывная проверка маршрута во время демонстрации не выполняется.

Собственный экран браузера всегда передаётся через CMNC. Адрес/порт CMNC из
настроек MikroTik нужны также для резервного маршрута выбранного ПК. Прямому режиму
нужен TCP 11400 на источнике, серверному — обычный Veyon-порт ПК (11100 по умолчанию)
и TCP-доступ получателей к адресу/порту ретранслятора. Через WireGuard серверная раздача
может сильнее загрузить туннель; прямая демонстрация в LAN избегает этого трафика.

Для маршрута через CMNC кадры ПК запрашиваются через WebAPI в исходном разрешении, с JPEG-качеством 100
по умолчанию. Ретранслятор не декодирует, не масштабирует и не перекодирует JPEG:
каждый получатель получает те же байты. Это исключает дополнительное ухудшение
качества на этапе раздачи; качество исходного захвата Veyon остаётся его пределом.
`CMNC_VEYON_DEMO_FPS` (1–30, по умолчанию 10) задаёт верхнюю частоту запроса кадров,
а не гарантированный FPS: фактическая частота зависит от скорости Veyon и сети.
`CMNC_VEYON_DEMO_QUALITY` (1–100) регулирует серверное JPEG-сжатие кадров ПК.
Частота и качество браузерного источника остаются 10 кадров/с и 1280×720.
При изменении разрешения ПК получателям отправляется RFB DesktopSize;
клиенты без этой возможности переподключаются. Каждый JPEG ограничен 4 МиБ минус
один байт (предел Tight); для слишком большого кадра появляется ошибка с предложением
снизить `CMNC_VEYON_DEMO_QUALITY`, без скрытого снижения качества.
При кратком сбое сохраняется последний кадр; при длительном отсутствии новых кадров
демонстрация завершается, а захват и память последнего кадра освобождаются.
Приватные ключи и токен подключения получателей в браузер не возвращаются.

Групповой запуск исключает устройства «Не ПК» целиком и пропускает защищённых
от массового Veyon-управления получателей. Защищённый ПК можно явно выбрать
источником или получателем отдельного действия. Источник и получатель отдельно
проверяются на доступ к аудитории. Одновременные демонстрации на пересекающихся
устройствах отклоняются, даже если их запускают разные пользователи.

Кнопка «Остановить демонстрацию» прекращает захват браузера и отправляет остановку
всем получателям, включая попытки с неопределённым результатом, и отменяет
задачу захвата ПК-источника, а также нативный DemoServer, если он был запущен.
Уход со страницы/вкладки действий также останавливает трансляцию. При потере
обратной связи с браузером сервер завершает демонстрацию через 60 секунд;
предельная продолжительность — 90 минут. Статус принятия команд приходит в обычном
всплывающем уведомлении. Он подтверждает принятие Veyon, а не визуальное появление
окна на каждом ПК.

После изменения настроек/кода:

```bash
bash scripts/compose-up.sh cmnc-inventory-service cmnc-veyon-service cmnc-api-gateway cmnc-web
```
