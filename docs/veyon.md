# Интеграция Veyon

## Состав

- `cmnc-veyon-proxy` — отдельный Veyon WebAPI Proxy 4.11.4 на Ubuntu 24.04.
  Используется официальный deb-пакет Veyon с закреплённой SHA-256, а не устаревший
  опубликованный образ. Он принимает WebAPI-запросы и подключается к Veyon Server на ПК.
- `cmnc-veyon-service` — хранение ключей, выбор ключа, соединения с устройствами,
  получение экрана и команды питания.
- API gateway проверяет доступ пользователя к аудитории при каждом запросе.
  Браузер не получает приватные ключи и внутренние идентификаторы подключений Veyon.

Proxy и интеграционный сервис работают только во внутренней сети Compose.
Их порты не публикуются на хост. API/Web не ждут Veyon при запуске; недоступность
Veyon влияет только на экран и управление питанием. Интеграционный сервис ждёт
готовности своего proxy-контейнера. База PostgreSQL и RabbitMQ ему не нужны.

Официальные материалы: [WebAPI](https://docs.veyon.io/en/latest/developer/webapi.html),
[WebAPI Proxy](https://github.com/veyon/webapi-proxy),
[релиз Veyon 4.11.4](https://github.com/veyon/veyon/releases/tag/v4.11.4).

## Настройка ключа

1. В Veyon Configurator экспортируйте **приватный** ключ нужной пары, например `CMNC`,
   в PEM-файл. На рабочих ПК должен быть соответствующий публичный ключ той же пары.
2. В приложении откройте редактирование MikroTik или аудитории. После создания
   нового объекта его нужно сохранить и снова открыть редактирование.
3. В блоке «Veyon — ключ аутентификации» укажите точное имя ключа (`CMNC`), выберите
   приватный PEM-файл либо вставьте его содержимое и нажмите «Сохранить ключ Veyon».
   Этот блок сохраняется отдельно от основной формы объекта.
4. Ключ MikroTik имеет приоритет над ключом аудитории. При ошибке этого ключа
   сервис не переключается на ключ аудитории автоматически. Удаление ключа MikroTik
   разрешает использование ключей отдельных аудиторий.

Поддерживаются незашифрованные приватные RSA-ключи PEM до 64 КБ. Сам ключ после
сохранения больше не возвращается в браузер: отображаются только имя и факт настройки.
Настраивать ключи могут пользователи с правом управления аудиториями/MikroTik.

На устройствах нужны работающая Veyon Service, аутентификация по ключам и разрешение
соответствующего доступа в Veyon. TCP-порт устройств по умолчанию — 11100;
его можно изменить переменной `CMNC_VEYON_TARGET_PORT` на сервере. WebAPI на каждом
рабочем ПК включать не требуется: его роль выполняет отдельный proxy-контейнер.
IP устройства должен находиться в подсети аудитории и быть доступен с сервера.

## Экран и питание

- В окне закреплённого устройства есть вкладка «Экран». Пока она открыта,
  частота обновления автоматически подстраивается под время загрузки и декодирования
  кадра, до 10 кадров/с. Параллельные запросы от одного просмотра не накапливаются. После ошибки
  повтор выполняется через 3 секунды. Кадры не сохраняются на диске и не кешируются.
- При закрытии вкладки/окна обновление прекращается; при скрытой вкладке браузера
  новые кадры не запрашиваются. Неактивные соединения Veyon закрываются автоматически.
- На вкладке «Инфо» доступны «Выключить» и «Перезагрузить» с подтверждением.
- На странице аудитории доступна «Выключить все» с обязательным подтверждением.
  Команда относится к закреплённым устройствам без защиты от массового управления,
  включая защищённые от отключения WAN.
  Защита WAN не является защитой от выключения питания.
- Просмотр и питание доступны всем, кто имеет доступ к данной аудитории/устройству.
  Команды не блокируются только из-за состояния online/offline из DHCP.
- Групповое выключение отправляет максимум четыре запроса одновременно и показывает
  число принятых команд и ошибок. Повторы команд питания автоматически не выполняются.
  Ответ «команда отправлена» означает принятие команды Veyon, а не подтверждение выключения ПК.

## Хранение и резервное копирование

Ключи хранятся зашифрованными в томе `cmnc_veyon_data` (SQLite + Fernet).
Ключ шифрования находится в том же защищённом томе; файлы доступны владельцу контейнера.
Резервная копия должна включать **весь том**, в том числе `master.key` и `keys.sqlite3`.
Стандартная резервная копия PostgreSQL эти данные не включает.
После потери `master.key` существующие зашифрованные ключи восстановить невозможно.
Не удаляйте том при обновлении контейнеров.

## Применение на сервере

Из корня проекта:

```bash
bash scripts/compose-up.sh cmnc-veyon-proxy cmnc-veyon-service cmnc-api-gateway cmnc-web
```

Скрипт с явно указанными сервисами использует `--no-deps`, поэтому proxy тоже указан
явно. При первом запуске будет создан том ключей. Миграции существующих баз не требуются.
Пакет proxy закреплён для архитектуры AMD64; для ARM64 нужен соответствующий официальный пакет.

Проверка:

```bash
docker compose -f infra/docker-compose.yml --env-file .env ps cmnc-veyon-proxy cmnc-veyon-service
docker logs --tail 100 cmnc-veyon-service
```

Проверка на тестовом стенде не выполняет команд питания на реальных ПК.
После установки загрузите ключ, откройте экран одного ПК и проверьте отдельную команду.

При подготовке первого кадра сервис ожидает изображение на уже открытом подключении.
Временный ответ FramebufferNotAvailable не закрывает сеанс и не запускает аутентификацию заново.


## Если изображение не появляется

После открытия вкладки «Экран» проверьте журнал интеграции:

```bash
docker logs --since 5m cmnc-veyon-service
```

Запись `Veyon authenticated` означает успешную аутентификацию. Если изображение
не поступает, запись `Veyon framebuffer unavailable` содержит возраст соединения,
идентификатор и длительность сеанса, признак входа пользователя либо статус ошибки
запроса этих сведений. Она выводится не чаще раза в минуту для соединения.
Приватный ключ, идентификатор подключения и имена пользователей не записываются.
Для диагностики также нужны версия Veyon на ПК и результат команды питания.
Не включайте отладочное логирование WebAPI: оно может раскрыть тело запроса с ключом.


## Режимы просмотра и несколько зрителей

Кнопка «На весь экран» использует полноэкранный режим браузера (выход — Esc).
Кнопка «В отдельном окне» открывает независимый просмотр;
окно может открыться вкладкой в зависимости от браузера. Разрешите всплывающие окна
для этого сайта. Встроенный просмотр на это время приостанавливается. При закрытии
отдельного окна просмотр возвращается в окно устройства, если оно ещё открыто.
Отдельное окно продолжает работать после закрытия окна устройства или перехода
в другую аудиторию. Оно использует обычную авторизацию приложения и проверку прав.
Скрытый просмотр приостанавливает получение кадров.

Соединение с ПК переиспользуется для одного адреса и пары ключ/имя ключа. Последний
успешный JPEG хранится только в памяти сервиса, до следующего кадра либо закрытия
соединения. Запросы на ту же ширину могут использовать его в течение 100 мс:
параллельные зрители не создают дополнительные подключения к ПК и не запрашивают
одинаковый кадр у proxy одновременно. Проверка прав выполняется на каждом запросе.
Кадры не хэшируются и не сохраняются на диск; браузеру отправляется `no-store`.
Сетевой трафик от сервера к браузерам растёт с числом зрителей.

Proxy настроен на интервал мониторинга 100 мс. Частота в браузере учитывает загрузку
и декодирование со сглаживанием; при задержках она снижается автоматически.
Это получение отдельных JPEG через WebAPI, не видеопоток с гарантированной частотой.


## Защита устройства от массового управления

На вкладке «Настройка» устройства есть флажок «Защита от массового управления».
По умолчанию он выключен, в том числе у существующих устройств после миграции.
При включении устройство исключается из массовых команд Veyon над аудиторией.
Исключение применяется на сервере; защищённые устройства не считаются ошибками,
а возвращаются в `skipped_count`. Подтверждение учитывает только устройства без защиты.
Если защищены все устройства, кнопка «Выключить все» недоступна.

Просмотр экрана, выключение и перезагрузка из окна конкретного устройства остаются
доступны пользователям с доступом к аудитории. Защита не влияет на WAN и WoL,
которые выполняются через MikroTik.

При обновлении требуется перезапуск сервиса аудиторий (он автоматически применяет
миграцию), затем API и веб-интерфейса. Контейнеры Veyon менять не требуется.
