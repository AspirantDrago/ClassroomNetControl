# Безопасное подтверждение WAN-политики

Результаты PolicySyncCompleted/Failed изменяют только устройства, чья аудитория
сейчас относится к router_id события. Снимок desired-blocklist содержит
`device_generations`: ID каждого устройства роутера и его ревизию, считанные
одним SQL-запросом вместе с желаемым состоянием. Включены также разрешённые
устройства, чтобы подтверждать удаление блокировки, а не только добавление.

Worker возвращает этот снимок в completed/failed, в том числе при исключении
после чтения политики. Обработчик использует точное совпадение пары ID/ревизия
и принадлежности роутеру. `policy_generation=max(...)` остаётся для совместимости
и диагностики, но больше не используется для массового подтверждения статусов.
Новая политика устройства с маленькой ревизией не подтверждается старым
ответом лишь потому, что у другого устройства счётчик достиг большого значения.

Успех может перевести pending/failed в applied, чтобы исправившаяся периодическая
синхронизация снимала прежнюю ошибку. Неуспех меняет только pending; запоздалый
failed не отменяет уже полученный applied. Старые события без device_generations
игнорируются с предупреждением; неизвестный снимок не позволяет подтвердить
какие-либо устройства. Следующий периодический цикл обновлённых сервисов
передаст полноценный снимок. Пустой снимок не меняет ни одной строки.

Запросы изменения WAN блокируют строку устройства, массовая операция берёт
строки в порядке ID. Это предотвращает потерю инкремента ревизии при параллельных
запросах. Редактирование IP/MAC/аудитории/закрепления/защиты тоже повышает ревизию
и ставит изменённую политику в pending. Закрепление/открепление повышает ревизию.

Миграция БД не нужна. Нужно обновить оба сервиса, поскольку меняются снимок
политики и формат результата. При смешанных версиях ошибочных подтверждений
не будет, но статусы могут временно оставаться pending до обновления worker.

```bash
bash scripts/compose-up.sh cmnc-classroom-service cmnc-policy-sync-service
```

Регрессионные тесты используют реальную SQLite-БД: два роутера, разные счётчики,
изменение устройства после чтения снимка, перевод устройства на другой роутер,
повторную доставку и старые сообщения без снимка. Отдельно проверяется
сохранение версий в completed/failed и исключениях worker.
